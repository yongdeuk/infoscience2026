카테고리마다 메뉴를 하나씩 골라 전체 잔반량이 가장 적은 조합을 찾습니다.

1단계 · 문제 발견 및 구조화

음식물 쓰레기는 환경·경제·사회 모든 측면에서 문제를 일으킵니다.

측면문제
환경쓰레기 처리 과정에서 나오는 메탄가스는 이산화탄소보다 25배나 강하다
경제음식물 쓰레기를 처리하는 데 매우 많은 비용이 든다
사회한쪽에서는 식량이 낭비되는데 다른 한편에서는 많은 사람이 굶주린다
지표값
하루 음식물 쓰레기 평균 발생량약 14,314톤
연간 처리 비용8천억 원
연간 온실가스 배출량885만 톤

출처: 환경부, 한국환경공단

수집한 데이터 — 영양 선생님 면담 결과 학생 1명이 남기는 평균 잔반은 약 170g(고등학생 연간 33kg ÷ 190일 ≈ 173g). 처리 비용은 1톤당 약 13~15만 원. 잔반 1kg당 1.65kg CO₂의 온실가스가 발생하며, 이는 소나무 다섯 그루가 흡수하는 양과 비슷합니다. 선호도가 높은 음식이 나오면 잔반량이 줄었습니다.

데이터 수집 시 유의 사항 — ① 다양한 데이터를 충분히 모아 문제의 본질을 이해한다 ② 배경 지식을 사전에 학습한다 ③ 면담 전에 질문 목록을 준비한다 ④ 출처를 명확히 해 신뢰할 수 있는 데이터를 모은다.

해결 방안 구조화 — 두 갈래로 정리됩니다.

  • 조리량 조정 ① 메뉴별 평균 잔반량을 분석해 적정 조리량 계산 ② 선호도 조사로 인기 메뉴는 늘리고 비인기 메뉴는 줄이기 ③ 급식을 먹지 않는 학생 수를 미리 조사해 식재료 낭비 줄이기
  • 학생 인식 개선 ① 잔반의 환경 영향 교육 ② 메뉴 계획에 학생 참여 ③ 먹겠다고 하고 먹지 않는 경우에 대한 책임 의식 부여

2단계 · 알고리즘 설계

각 카테고리에서 메뉴를 하나씩 골라 전체 잔반량이 최소가 되는 조합을 찾습니다. 카테고리별 선택을 부분 문제로 나누고, 이미 계산한 상태는 저장해 두어 중복 계산을 피합니다.

3단계 · 프로그램 작성

① 데이터 입력 — 딕셔너리로 메뉴와 카테고리 정의

menu_data = {
    '닭고기': {'waste': 40}, '돼지고기': {'waste': 50}, '소고기': {'waste': 30},
    '브로콜리': {'waste': 20}, '시금치': {'waste': 25}, '양배추': {'waste': 35},
    '미역국': {'waste': 50}, '된장국': {'waste': 20}, '김치찌개': {'waste': 40},
    '김치': {'waste': 15}, '멸치볶음': {'waste': 35}, '나물': {'waste': 25}
}

categories = {
    '고기': ['닭고기', '돼지고기', '소고기'],
    '야채': ['브로콜리', '시금치', '양배추'],
    '국':   ['미역국', '된장국', '김치찌개'],
    '반찬': ['김치', '멸치볶음', '나물']
}

② 알고리즘 구현 — 동적 계획법

def dp_minimize_waste(menu_data, categories):
    category_keys = list(categories.keys())   # (1) 카테고리 개수 계산
    n = len(category_keys)                    #     여기서는 4
    dp = {}                                   #     동적 테이블

    def get_min_waste(index, chosen):
        if index == n:                        # (2)-① 종료 조건
            return 0, []                      #      모두 골랐으면 낭비 0
        if (index, tuple(chosen)) in dp:      # (2)-② 중복 계산 확인
            return dp[(index, tuple(chosen))]

        min_waste = float('inf')              # (2)-③ 초기화
        best_combination = []

        current_category = category_keys[index]          # (3) 최소 조합 찾기
        for menu in categories[current_category]:
            if menu not in chosen:
                chosen.append(menu)
                waste, combination = get_min_waste(index + 1, chosen)
                waste += menu_data[menu]['waste']        # 현재 메뉴의 잔반 더하기
                if waste < min_waste:
                    min_waste = waste
                    best_combination = [menu] + combination
                chosen.pop()                             # 되돌리기

        dp[(index, tuple(chosen))] = (min_waste, best_combination)
        return min_waste, best_combination

    return get_min_waste(0, [])               # (4) 계산 시작

③ 메인 함수 실행 및 결과 출력

min_waste, best_menu = dp_minimize_waste(menu_data, categories)
print('최적 메뉴 조합:', best_menu)
print('최소 잔반량:', min_waste, 'g')
# 최적 메뉴 조합: ['소고기', '브로콜리', '된장국', '김치']
# 최소 잔반량: 85 g

2-1 프로젝트 ② 탄소 발자국 계산 15주차

장소를 노드, 이동할 때 나오는 탄소 배출량을 가중치로 놓고 최소 배출 경로를 찾습니다.

항목내용
문제 정의일상 활동의 탄소 발자국을 계산하고 줄일 방법을 제안한다
기본 공식탄소 발자국 = 활동량 × 배출 계수

알고리즘다익스트라 알고리즘 — 한 노드에서 다른 모든 노드까지의 최단(최소 배출) 경로
연결되는 단원Ⅱ-1-2 큐(우선순위 큐), Ⅱ-2-2 그래프
우선순위 큐를 쓰면 지금까지 배출량이 가장 적은 경로부터 먼저 처리하고, 이미 확정된 노드는 다시 보지 않습니다. Ⅲ단원에서 배운 탐색 공간 배제가 그대로 적용된 사례입니다. UN 지속가능발전목표 13. 기후 행동과 연결됩니다.

1단계 · 문제 발견 및 구조화

탄소 발자국은 개인·기업·국가가 활동하거나 상품을 생산·소비하는 과정에서 발생하는 온실가스, 특히 이산화탄소의 총량입니다. 클수록 배출량이 많다는 뜻이며, 줄이면 지구 온난화 문제 해결에 기여합니다.

수집할 데이터 — ① 교통수단 사용 정보(주요 수단, 주행 거리, 연비) ② 가정 내 에너지 소비량(전기·가스·물) ③ 식품 소비 정보(음식 종류, 수입 여부) ④ 제품 사용과 폐기 정보(사용 기간, 폐기 시 배출량)

분석할 내용 — ① 활동별 탄소 배출 영향 비교 ② 개인 활동에 따른 배출량 계산 ③ 개인별 감축 목표 설정(자전거로 등교하기, 샤워 10분 안에 끝내기, 노트북 사용 1시간 줄이기 등)

해결 방안 구조화 — ① 대안 행동 제안(자동차 대신 자전거·대중교통, 재활용 가능 제품 구매) ② 탄소 배출 시각화(실천한 행동이 얼마나 줄였는지 그래프로 확인) ③ 사회적 활동과 연계(학교·지역 사회의 탄소 중립 챌린지 참여)

② 알고리즘 구현 — 다익스트라

import heapq

def dijkstra(graph, start):
    # (1) 초기 설정 — 모든 장소를 무한대로, 출발점만 0
    co2 = {node: float('inf') for node in graph}
    co2[start] = 0
    priority_queue = [(0, start)]      # (배출량, 장소) 튜플
    step_count = 1

    while priority_queue:
        # (2) 방문할 장소 선택 — 배출량이 가장 적은 것부터
        current_co2, current_node = heapq.heappop(priority_queue)
        if current_co2 > co2[current_node]:
            continue                   # 이미 더 좋은 경로가 있으면 무시

        # (3) 배출량 업데이트
        for neighbor, co2_amount in graph[current_node].items():
            new_co2 = current_co2 + co2_amount
            if new_co2 < co2[neighbor]:            # 더 적으면 갱신
                co2[neighbor] = new_co2
                heapq.heappush(priority_queue, (new_co2, neighbor))

        # (4) 알고리즘 단계 출력 — 과정을 눈으로 확인
        print(f'[{step_count}단계] 현재 장소: {current_node}, '
              f'누적 배출량: {current_co2}')
        print('  배출량 상태:', co2)
        print('  우선순위 큐:', priority_queue)
        step_count += 1

    return co2
float('inf')로 초기화하는 이유는 아직 그 장소로 가는 경로를 찾지 못했음을 나타내기 위해서입니다. heapq는 파이썬의 우선순위 큐 모듈로, 가장 작은 값을 먼저 꺼냅니다.

① Student 클래스

class Student:
    def __init__(self, name, fixed_seat=None, preferred_seat=None,
                 previous_seat=None, previous_partner=None):
        self.name = name
        self.fixed_seat = fixed_seat
        # 기본값을 딕셔너리로 직접 쓰지 않는 이유는 아래 설명 참고
        self.preferred_seat = preferred_seat if preferred_seat else {'front': 0, 'back': 0}
        self.previous_seat = previous_seat
        self.previous_partner = previous_partner
매개 변수 기본값에 딕셔너리를 쓰면 안 되는 이유 — 기본값 딕셔너리는 함수가 호출될 때마다 새로 만들어지지 않고 하나의 객체를 모든 호출이 공유합니다. 한 학생의 선호를 바꿨는데 다른 학생까지 바뀌는 사고가 납니다. 그래서 기본값은 None으로 두고 함수 안에서 새로 만들어 줍니다.

② Classroom 클래스

class Classroom:
    def __init__(self, rows, cols, allow_prev_seat):
        self.rows = rows
        self.cols = cols
        self.seats = [[None for _ in range(cols)] for _ in range(rows)]
        self.allow_prev_seat = allow_prev_seat    # 이전 자리 허용 여부

    def assign_seat(self, row, col, student):     # 특정 자리에 학생 배정
        self.seats[row][col] = student

    def display_seats(self):                      # 현재 배치 상태 출력
        for row in self.seats:
            for student in row:
                if isinstance(student, Student):
                    print(f'{student.name:<6}', end='')   # 왼쪽 정렬, 너비 6
                else:
                    print(f'{"빈자리":<6}', end='')
            print()
        print()

‘이전 짝 피하기’ 기능을 새로 추가하면서 생기는 오류를 찾아 고쳐 봅니다.

  1. students.csv와 Student 클래스에 이전 짝(previous_partner) 정보를 추가한다
  2. Classroom 클래스에 allow_prev_partner 속성을 추가하고, 객체 생성 시 True/False를 저장한다
  3. load_students_from_csv()가 이전 짝 정보도 함께 읽어 오도록 한다
  4. 배치할 때 is_safe() 함수에서 현재 짝이 이전 짝인지 검사하도록 한다
발생하는 오류 — 앞줄에 고정 자리 2명, 앞자리 선호 학생 2명이 있고 이전 자리·이전 짝을 모두 허용하지 않으면 조건이 서로 충돌해 배정 실패가 납니다. (“구정식은 이전 짝꿍인 강민재의 옆자리이기 때문에 (0, 3)에 앉을 수 없습니다” → “선호도 반영한 앞자리 배정 실패”) 조건이 너무 많아 해가 존재하지 않는 상황을 어떻게 처리할지가 디버깅의 핵심입니다.
