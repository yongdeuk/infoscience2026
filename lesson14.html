    재귀 함수가 종료되는 순간 — 종료 조건의 중요성
    
      
    종료 조건이 없으면 재귀 함수는 무한 루프에 빠집니다. 프로그램이 끝나지 않고 메모리를 낭비하다가 비정상 종료될 수 있으므로, 재귀 함수를 설계할 때는 반드시 종료 조건을 넣어야 합니다. 방법은 두 가지가 대표적입니다.
    
      
    ① 시도 횟수를 제한하여 종료 — 카운트다운 방식
    
      
    def countdown(n):
    if n == 0:                    # 기본 단계(종료 조건)
        return '종료'
    else:
        print(n, end=' ')
        return countdown(n - 1)

print(countdown(5))               # 5 4 3 2 1 종료
    
      
    ② 특정 목표에 도달하면 종료 — 팩토리얼은 n이 1이 되면 멈춤
    
      
    def factorial(n):
    if n == 0 or n == 1:          # 기본 단계
        return 1
    else:
        return 

print(factorial(5))               # 120
    
    
    

    재귀 호출의 최대 깊이 — 파이썬은 메모리 부족을 막기 위해 재귀 호출 횟수에 한계를 둡니다. import sys; print(sys.getrecursionlimit())로 확인할 수 있고, 필요하면 조정할 수 있습니다.

from ColabTurtle.Turtle import *

initializeTurtle(initial_speed=13)   # 13이 가장 빠름
color('green')

def draw_tree(length, depth):
    if depth == 0:                   # 기본 단계: 더 그리지 않고 종료
        return
    else:
        forward(length)
        left(45)
        draw_tree(length * 0.7, depth - 1)     # 왼쪽 가지
        right(90)
        draw_tree(length * 0.7, depth - 1)     # 오른쪽 가지
        left(45)
        backward(length)             # 원래 자리로 되돌아오기

draw_tree(80, 5)

    힌트
    1!은 1이니 n이 1일 때 멈춰요. 재귀 호출에는 한 단계 작은 n - 1을 넘겨요.
    정답 코드 보기
    def factorial(n, depth=0):
    print('  ' * depth + f'factorial({n}) 호출')
    if n == 1:
        result = 1
    else:
        result = n * factorial(n - 1, depth + 1)
    print('  ' * depth + f'factorial({n}) = {result} 반환')
    return result

factorial(4)
    고치기
    홀수에서 멈추지 않는 카운트다운
    2씩 줄이는 카운트다운이에요. 10에서는 잘 되는데 5에서는 RecursionError가 나요. 5 → 3 → 1 → -1 …로 0을 건너뛰기 때문이에요. 종료 조건을 고쳐 두 줄 모두 발사!로 끝나게 하세요.
    def countdown(n):
    if n == 0:
        return '발사!'
    print(n, end=' ')
    return countdown(n - 2)

print(countdown(10))
print(countdown(5))

    4확인 문제
    

    Q1power(2, 3)을 계산할 때 가장 먼저 값이 확정되는 호출은?
    해설 — 끝까지 내려가 기본 단계인 power(2, 0) = 1이 먼저 확정되고, 거꾸로 올라오며 2, 4, 8이 확정돼요.
    

    Q2파이썬이 재귀 호출 깊이에 한계를 두는 이유로 알맞은 것은?
    해설 — 호출마다 돌아갈 자리를 스택에 기억해야 해서, 너무 깊어지면 메모리를 많이 써요. sys.getrecursionlimit()으로 한계를 볼 수 있어요.
