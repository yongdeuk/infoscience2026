용어 사전

함수 functionⅠ
특정 작업을 수행하는 코드를 하나로 묶고 이름을 붙인 것. 한 번 정의해 두면 이름으로 여러 번 불러 쓸 수 있다. 본문 →
내장 함수 built-in functionⅠ
파이썬에 처음부터 들어 있어 따로 정의하지 않고 쓰는 함수. print(), len(), max() 등. 본문 →
사용자 정의 함수 user-defined functionⅠ
프로그래머가 def로 직접 만든 함수. 본문 →
함수 정의 definitionⅠ
def 함수이름(매개 변수): 형식으로 함수가 할 일을 적어 두는 것. 정의만으로는 실행되지 않는다. 본문 →
함수 호출 callⅠ
정의된 함수 이름 뒤에 괄호를 붙여 실제로 실행시키는 것. 호출하면 실행 흐름이 함수 안으로 들어갔다가 끝나면 돌아온다. 본문 →
매개 변수 parameterⅠ
함수를 정의할 때 괄호 안에 적어, 전달받은 값을 담는 변수. 본문 →
인수 argumentⅠ
함수를 호출할 때 괄호 안에 넣어 실제로 전달하는 값. 인수가 매개 변수에 차례로 담긴다. 본문 →
반환값 return valueⅠ
함수가 일을 마치고 return으로 호출한 곳에 돌려주는 결과. 본문 →
return returnⅠ
값을 돌려주는 역할과 함수를 즉시 끝내는 역할을 함께 한다. 값 없이 끝나면 None을 돌려준다. 본문 →
지역 변수 local variableⅠ
함수 안에서 만들어져 그 함수 안에서만 쓸 수 있는 변수. 함수가 끝나면 사라진다. 본문 →
전역 변수 global variableⅠ
함수 밖에서 만들어져 프로그램 전체에서 읽을 수 있는 변수. 함수 안에서 값을 바꾸려면 global 선언이 필요하다. 본문 →
변수의 범위 scopeⅠ
변수를 사용할 수 있는 영역. 지역 범위와 전역 범위로 나뉜다. 본문 →
기본값 매개 변수 default parameterⅠ
인수를 생략하면 미리 정해 둔 값이 쓰이는 매개 변수. 예: def greet(name='친구'). 본문 →
가변 인수 매개 변수 *argsⅠ
개수가 정해지지 않은 인수를 튜플로 한꺼번에 받는 매개 변수. 이름 앞에 *를 붙인다. 본문 →
클래스 classⅠ
같은 종류의 객체가 가질 속성(데이터)과 메서드(기능)를 정의한 설계도. 본문 →
객체 objectⅠ
클래스로부터 만들어진 실체. 같은 클래스로 여러 객체(인스턴스)를 만들 수 있다. 본문 →
메서드 methodⅠ
클래스 안에 정의된 함수. 객체 이름 뒤에 점을 찍어 obj.method()처럼 호출한다. 본문 →
생성자 __init__Ⅰ
객체가 만들어질 때 자동으로 실행되어 속성의 처음 값을 정하는 특별한 메서드. 본문 →
self selfⅠ
메서드 안에서 ‘지금 이 객체 자신’을 가리키는 첫 번째 매개 변수. 본문 →
모듈 moduleⅠ
함수·클래스·변수를 모아 둔 파이썬 파일(.py). import로 가져와 쓴다. 본문 →
패키지 packageⅠ
관련된 모듈 여러 개를 폴더로 묶은 것. 본문 →
라이브러리 libraryⅠ
자주 쓰는 기능을 모아 둔 모듈·패키지의 묶음. random, math 같은 표준 라이브러리와 따로 설치하는 외부 라이브러리가 있다. 본문 →
재귀 recursionⅠ
함수가 자기 자신을 다시 호출하는 구조. 큰 문제를 같은 모양의 더 작은 문제로 바꾸어 푼다. 본문 →
재귀 함수 recursive functionⅠ
실행 중에 자기 자신을 호출하는 함수. 반드시 종료 조건이 있어야 한다. 본문 →
종료 조건 base caseⅠ
더 이상 자기 자신을 호출하지 않고 바로 답을 내는 경우. 없으면 호출이 끝없이 이어져 RecursionError가 난다. 본문 →
재귀 관계 recurrence relationⅠ
앞의 항으로 다음 항을 나타내는 식. 예: n! = n × (n−1)!. 본문 →
수학적 귀납법 mathematical inductionⅠ
첫 번째 경우가 참이고, k번째가 참이면 k+1번째도 참임을 보여 모든 경우가 참임을 증명하는 방법. 재귀의 사고방식과 같다. 본문 →
호출 스택 call stackⅠ
호출된 함수들이 차례로 쌓이는 메모리 공간. 나중에 호출된 함수가 먼저 끝나므로 스택 구조다. 본문 →
하노이 탑 Tower of HanoiⅠ
원판 n개를 규칙대로 옮기는 퍼즐. n−1개를 옮기는 문제로 나누어 재귀로 풀며 최소 2ⁿ−1번 이동한다. 본문 →
데이터 구조 data structureⅡ
데이터를 효율적으로 저장·관리하기 위한 형태. 선형 구조(리스트·스택·큐)와 비선형 구조(트리·그래프)로 나뉜다. 본문 →
선형 구조 linear structureⅡ
데이터가 한 줄로 앞뒤 관계를 이루는 구조. 리스트, 스택, 큐, 덱. 본문 →
비선형 구조 non-linear structureⅡ
하나의 데이터 뒤에 여러 데이터가 이어질 수 있는 구조. 트리, 그래프. 본문 →
스택 stackⅡ
한쪽 끝(top)으로만 넣고 빼는 구조. 나중에 넣은 것이 먼저 나온다. 본문 →
LIFO Last In First OutⅡ
후입선출. 마지막에 들어온 데이터가 가장 먼저 나가는 방식. 스택의 특징. 본문 →
push pushⅡ
스택의 top에 데이터를 넣는 연산. 파이썬 리스트에서는 append(). 본문 →
pop popⅡ
스택의 top에서 데이터를 꺼내는 연산. 파이썬 리스트에서는 pop(). 본문 →
peek peek / topⅡ
데이터를 꺼내지 않고 top에 있는 값만 확인하는 연산. stack[-1]. 본문 →
오버플로·언더플로 overflow / underflowⅡ
가득 찬 곳에 넣으려 할 때(오버플로), 비어 있는데 꺼내려 할 때(언더플로) 생기는 오류 상황. 본문 →
큐 queueⅡ
한쪽(rear)으로 넣고 반대쪽(front)으로 빼는 구조. 먼저 넣은 것이 먼저 나온다. 본문 →
FIFO First In First OutⅡ
선입선출. 먼저 들어온 데이터가 먼저 나가는 방식. 큐의 특징. 본문 →
enqueue / dequeue enqueue / dequeueⅡ
큐의 rear에 넣는 연산(enqueue)과 front에서 꺼내는 연산(dequeue). 본문 →
덱 dequeⅡ
양쪽 끝에서 모두 넣고 뺄 수 있는 구조. collections.deque. 본문 →
우선순위 큐 priority queueⅡ
들어온 순서가 아니라 우선순위가 높은 데이터부터 꺼내는 큐. heapq로 구현. 본문 →
트리 treeⅡ
노드들이 간선으로 연결되어 계층을 이루고 사이클이 없는 구조. 가족 관계도, 폴더 구조. 본문 →
노드 nodeⅡ
트리·그래프에서 데이터를 담는 하나하나의 점. 본문 →
간선 edgeⅡ
노드와 노드를 잇는 선. 노드가 n개인 트리의 간선은 n−1개. 본문 →
루트 노드 rootⅡ
트리의 맨 위, 부모가 없는 노드. 본문 →
단말 노드 leafⅡ
자식이 없는 노드. 잎 노드라고도 한다. 본문 →
부모·자식·형제 parent / child / siblingⅡ
간선으로 연결된 위아래 노드 관계. 같은 부모를 가진 노드끼리 형제. 본문 →
차수 degreeⅡ
한 노드가 가진 자식의 수(트리) 또는 연결된 간선의 수(그래프). 본문 →
깊이·높이 depth / heightⅡ
루트에서 그 노드까지의 거리가 깊이, 트리에서 가장 깊은 노드의 깊이가 높이. 본문 →
서브 트리 subtreeⅡ
한 노드와 그 아래 자손들로 이루어진 작은 트리. 본문 →
이진 트리 binary treeⅡ
모든 노드의 자식이 최대 두 개(왼쪽·오른쪽)인 트리. 본문 →
이진 탐색 트리 binary search treeⅡ
왼쪽 서브 트리에는 작은 값, 오른쪽에는 큰 값이 오도록 정리한 이진 트리. 값을 찾을 때 한 번에 한쪽을 버린다. 본문 →
트리 순회 traversalⅡ
트리의 모든 노드를 한 번씩 방문하는 방법. 전위(루트→왼→오), 중위(왼→루트→오), 후위(왼→오→루트). 본문 →
그래프 graphⅡ
노드(정점)와 간선으로 대상 사이의 관계를 나타낸 구조. 지하철 노선도, SNS 친구 관계. 본문 →
방향·무방향 그래프 directed / undirectedⅡ
간선에 방향이 있으면 방향 그래프, 양쪽으로 오갈 수 있으면 무방향 그래프. 본문 →
가중치 그래프 weighted graphⅡ
간선마다 거리·시간·비용 같은 값(가중치)이 붙은 그래프. 본문 →
인접 행렬 adjacency matrixⅡ
노드 i와 j가 연결되면 [i][j]를 1(또는 가중치)로 적는 2차원 표. 연결 여부 확인이 빠르다. 본문 →
인접 리스트 adjacency listⅡ
각 노드마다 연결된 노드 목록을 저장하는 방식. 간선이 적을 때 메모리를 아낀다. 본문 →
깊이 우선 탐색 DFSⅡ
갈 수 있는 데까지 깊이 들어갔다가 막히면 되돌아오는 탐색. 스택(또는 재귀)을 쓴다. 본문 →
너비 우선 탐색 BFSⅡ
시작점에서 가까운 노드부터 한 겹씩 넓혀 가는 탐색. 큐를 쓰며, 간선 수 기준 최단 경로를 찾는다. 본문 →
알고리즘 algorithmⅢ
문제를 해결하기 위한 명확하고 유한한 절차. 입력·출력·명확성·유한성·효율성을 갖춘다. 본문 →
시간 복잡도 time complexityⅢ
입력 크기 n이 커질 때 알고리즘의 연산 횟수가 얼마나 늘어나는지 나타낸 것. 본문 →
공간 복잡도 space complexityⅢ
알고리즘이 실행되는 동안 필요한 메모리의 양. 본문 →
빅오 표기법 Big-O notationⅢ
최악의 경우 연산 횟수의 증가 정도를 가장 큰 차수만 남겨 나타내는 방법. O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2ⁿ). 본문 →
최선·평균·최악 best / average / worstⅢ
같은 알고리즘도 입력에 따라 걸리는 시간이 다르다. 보통 최악의 경우로 성능을 비교한다. 본문 →
상태 공간 state spaceⅢ
문제에서 나올 수 있는 모든 상태와 상태 사이의 이동을 모은 것. 초기 상태·목표 상태·연산자로 정의한다. 본문 →
탐색 공간 search spaceⅢ
답을 찾기 위해 살펴봐야 하는 후보 전체. 본문 →
전체 탐색 exhaustive searchⅢ
모든 후보를 빠짐없이 확인하는 방법. 브루트 포스. 정확하지만 후보가 많으면 느리다. 본문 →
순차 탐색 sequential searchⅢ
처음부터 하나씩 차례로 비교하는 탐색. O(n). 본문 →
탐색 공간 배제 pruningⅢ
답이 없다고 확실한 부분을 아예 살펴보지 않고 버려 탐색 시간을 줄이는 전략. 본문 →
이진 탐색 binary searchⅢ
정렬된 자료에서 가운데 값과 비교해 절반씩 버리며 찾는 방법. O(log n). 본문 →
탐욕 알고리즘 greedyⅢ
매 순간 가장 좋아 보이는 선택을 하는 방법. 빠르지만 항상 최적해를 보장하지는 않는다. 본문 →
최적해 optimal solutionⅢ
가능한 해 가운데 가장 좋은 해. 본문 →
백트래킹 backtrackingⅢ
해를 하나씩 만들어 가다가 조건을 어기면 바로 이전 단계로 되돌아가 다른 선택을 하는 방법. N-퀸 문제. 본문 →
분기 한정 branch and boundⅢ
지금까지 찾은 가장 좋은 해보다 나아질 수 없는 가지는 더 탐색하지 않는 방법. 본문 →
분할 정복 divide and conquerⅢ
문제를 작은 문제로 나누고(분할), 각각 풀고(정복), 결과를 합쳐(결합) 원래 문제를 푸는 방법. 본문 →
퀵 정렬 quick sortⅢ
기준값(피벗)보다 작은 쪽과 큰 쪽으로 나누어 재귀적으로 정렬. 평균 O(n log n). 본문 →
합병 정렬 merge sortⅢ
반으로 나누어 각각 정렬한 뒤 두 정렬된 리스트를 합친다. 항상 O(n log n). 본문 →
피벗 pivotⅢ
퀵 정렬에서 리스트를 나누는 기준이 되는 값. 본문 →
동적 계획법 dynamic programmingⅢ
작은 부분 문제의 답을 저장해 두고 큰 문제를 풀 때 다시 쓰는 방법. 같은 계산을 반복하지 않는다. 본문 →
메모이제이션 memoizationⅢ
한 번 계산한 결과를 저장해 두었다가 같은 호출이 오면 바로 꺼내 쓰는 기법(하향식). 본문 →
상향식 bottom-upⅢ
가장 작은 부분 문제부터 표를 채워 올라가며 답을 구하는 동적 계획법 방식. 본문 →
최적 부분 구조 optimal substructureⅢ
큰 문제의 최적해가 부분 문제의 최적해로 이루어지는 성질. 동적 계획법을 쓸 수 있는 조건. 본문 →
중복 부분 문제 overlapping subproblemsⅢ
같은 부분 문제가 여러 번 반복해서 나타나는 성질. 피보나치 수열의 재귀 호출. 본문 →
배낭 문제 knapsack problemⅢ
무게 제한 안에서 가치의 합이 최대가 되도록 물건을 고르는 문제. 0-1 배낭은 동적 계획법으로 푼다. 본문 →
문제 해결 5단계 problem solvingⅣ
