알고리즘

같은 문제를 푸는 방법은 여럿이다. 그중 어떤 방법이 더 효율적인지 판단하고, 문제의 성격에 맞는 전략을 고르는 법을 배운다.

1-1 알고리즘의 이해 10주차

알고리즘은 문제를 해결하는 체계적인 절차·방법입니다. 접근 방식에 따라 크게 두 갈래로 나뉩니다.

알고리즘이 갖춰야 할 조건 — 입출력(입력을 받아 1개 이상 결과가 나옴) · 유한성(언젠가 끝남) · 명확성(각 단계가 모호하지 않음) · 수행 가능성(실제로 실행 가능함).
전략한 줄 요약학생들의 생각으로 옮기면
탐욕법매 순간 최선의 선택“지금까지 본 사람 중 가장 빠르니까 바로 뽑아야지”
분기 한정법불필요한 경로는 배제“조건에 맞는 선수만 골라서 면접을 봐야겠어”
분할 정복법작은 문제로 분해하여 해결“각 그룹에서 뽑힌 선수들만 모아서 선발해야겠군”
동적 계획법이전에 풀었던 해답을 기억해 활용“앞 선수들의 특징을 기억했다가 다음 선수와 비교해야지”
역량 키우기 · 수행 활동

놀이공원 최적 경로 계획하기 — 정문에서 출발해 놀이기구를 모두 한 번씩만 타고 정문으로 돌아와야 한다. 제한된 시간 안에 최대한 많이 타려면 어떤 경로로 이동해야 할까?

네 가지 전략을 각각 적용하면 어떤 계획이 나오는지 적어 보고, 내가 고른 알고리즘과 그 이유를 친구들과 이야기해 보자.

  • 탐욕법 — 현재 위치에서 가장 가까운 놀이기구부터 탄다
  • 분기 한정법 — 남은 시간보다 이동 시간이 긴 놀이기구는 후보에서 뺀다
  • 분할 정복법 — 놀이공원을 구역으로 나눠 구역별 경로를 짠 뒤 합친다
  • 동적 계획법 — 이미 계산한 구간의 최적 경로를 저장해 두고 재사용한다

단원을 다 배운 뒤 지금 쓴 생각과 비교해 보면, 내 판단이 어떻게 달라졌는지 알 수 있습니다.

1-2 알고리즘 복잡도 10주차

“얼마나 빠른가”를 컴퓨터 성능과 상관없이 비교하는 방법이 필요합니다.

시간 복잡도는 실행에 필요한 연산의 수, 공간 복잡도는 사용하는 메모리의 양입니다. 둘은 대체로 반비례하므로 보통 시간 복잡도를 기준으로 평가합니다.

막대 길이는 가장 큰 값을 기준으로 한 상대 비율입니다. n을 키울수록 O(n²)만 혼자 치솟는 것을 볼 수 있습니다.

코드를 보고 시간 복잡도 읽기

O(n) — 반복문이 n번 돈다

sum = 0
n = int(input('자연수 입력:'))
for num in range(n + 1):     # n이 커지면 더하는 횟수도 그만큼 늘어남
    sum += num
print(f'1부터 {n}까지의 합은 {sum}입니다.')

O(1) — 공식으로 한 번에 끝낸다

n = int(input('자연수 입력:'))
sum = int(n * (n + 1) / 2)   # n과 관계없이 실행 시간이 거의 같음
print(f'1부터 {n}까지의 합은 {sum}입니다.')

O(n²) — 반복문이 이중으로 겹친다 (선택 정렬)

nums = [8, 2, 5, 11, 26, 33, 1, 88, 52, 7, 19, 75, 26, 44, 11, 62, 9, 15, 21, 30]
n = int(input('20 이하의 자연수 입력:'))

for i in range(n):                  # 바깥쪽 반복문 n번
    min, k = nums[i], i
    for j in range(i, n):           # 안쪽 반복문 최대 n번
        if min > nums[j]:
            min = nums[j]
            k = j
    del nums[k]
    nums.insert(i, min)
print('크기순 값\\n', nums[:n])
탐색의 예 — 정수 10개에서 앞에서부터 차례로 비교해 값을 찾을 때, 최선은 맨 앞에 있어 1번, 최악은 맨 뒤에 있어 10번 비교합니다. 이 알고리즘의 시간 복잡도는 O(n)입니다.

  1. 재귀 함수로 1부터 n까지의 합 구하기 — 호출이 몇 번 일어나는가?
  2. 배열에서 최댓값을 찾는 두 가지 알고리즘의 시간 복잡도를 비교하기
핵심 포인트
  • 빅오는 최악의 경우를 나타낸다. 상수와 낮은 차수 항은 버린다.
  • 반복문 하나 → O(n), 중첩 반복문 → O(n²), 범위를 절반씩 줄임 → O(log n).
  • 공식 한 줄로 끝나면 O(1). sum = n*(n+1)//2 가 반복문보다 압도적으로 빠른 이유.

2-1 탐색 기반 알고리즘의 이해 11주차

가능한 모든 경우를 “상태 공간”으로 그려 놓고, 그 안에서 답을 찾아가는 방식입니다.

문제는 초기 상태 · 목표 상태 · 행동 세 요소로 정의됩니다. 초기 상태에서 목표 상태까지 가는 동안 거칠 수 있는 모든 상태의 집합이 상태 공간입니다.

전체 탐색 알고리즘의 설계 5단계

무작위로 섞인 열쇠 중 문을 여는 열쇠를 찾으려면 하나씩 다 꽂아 보면 됩니다. 이렇게 모든 경우를 시도하는 것이 브루트 포스 알고리즘(brute = 단순히, force = 힘)입니다.

  1. 문제 정의 — 문제를 정확히 이해하고 가능한 해의 범위를 정한다
  2. 상태 공간 생성 — 가능한 모든 상태(해)를 나열한다
  3. 순회 방법 결정 — 재귀 함수 또는 반복문으로 상태 공간을 훑는다
  4. 유효성 검사 — 각 상태가 문제 조건을 만족하는지 확인한다
  5. 최적의 해 선택 — 조건을 만족하는 상태 중 최선을 고른다

순차 탐색은 처음부터 끝까지 하나씩 확인합니다. 정렬되어 있지 않아도 쓸 수 있지만 시간 복잡도는 O(n)입니다.

def linear_search(arr, target):
    for i in range(len(arr)):
        if arr[i] == target:
            return i
    return -1

arr = [9, 5, 8, 3, 7]
print(f'Target found at index: {linear_search(arr, 8)}')   # 2

선형 전체 탐색의 예 — ‘한수’의 개수 세기

각 자릿수가 등차수열을 이루는 수를 한수라고 합니다. 123은 차이가 모두 1이라 한수이고, 124는 차이가 1과 2로 달라 한수가 아닙니다. 한 자리 수와 두 자리 수는 모두 한수입니다.

def is_hansu(number):
    if number < 100:
        return True                      # 한/두 자리 수는 모두 한수
    str_num = str(number)
    diff1 = int(str_num[0]) - int(str_num[1])
    diff2 = int(str_num[1]) - int(str_num[2])
    return diff1 == diff2

def count_hansu(N):
    count = 0
    for i in range(1, N + 1):            # 1부터 N까지 순차 탐색
        if is_hansu(i):
            count += 1
    return count

N = int(input('N을 입력하세요: '))
print(count_hansu(N))

비선형 전체 탐색 — 3×3 행렬에서 최소 합 찾기

행과 열이 겹치지 않게 숫자 3개를 골라 합이 최소가 되게 하는 문제입니다. 첫 행에서 3개, 둘째 행에서 남은 2개, 셋째 행에서 1개 — 경우의 수는 3! = 6가지이고, n×n이면 n!가지입니다.

m = [[1, 5, 3], [2, 5, 7], [9, 3, 5]]
visited = [False] * 3                # 열 사용 여부
min_solution = float('inf')

def find_min_sum(row, current_sum):
    global min_solution
    if row == 3:                     # 마지막 행까지 모두 선택했으면
        min_solution = min(min_solution, current_sum)
        return
    for col in range(3):
        if not visited[col]:         # 아직 쓰지 않은 열이면
            visited[col] = True
            find_min_sum(row + 1, current_sum + m[row][col])
            visited[col] = False     # 되돌리기 — 다른 경로도 탐색

find_min_sum(0, 0)
print('최소 합:', min_solution)      # 8  (3 + 2 + 3)
전체 탐색은 최적해를 보장하지만, 상태 공간이 n!처럼 폭발적으로 커지면 계산 비용과 시간이 감당하기 어려워집니다. 그래서 다음 절에서 탐색 공간을 배제하는 방법을 배웁니다.
스스로 해결하기
  1. 집에서 학교까지 가는 경로를 그래프로 그리고, 갈 수 있는 모든 경우의 수를 상태 공간으로 표현해 보자.
  2. 다음 상황에 알맞은 탐색을 골라 보자. ① 정렬된 리스트에서 특정 항목 찾기 ② 조직도에서 상위 관리자부터 부서별로 직원 찾기 ③ 진로 사이트에서 조건에 맞는 학과 찾기
    (선형/비선형 · 전체/부분)

탐욕 알고리즘 — 매 순간 가장 좋아 보이는 선택

지금 이 단계에서 최선인 것을 고르고 되돌아보지 않습니다. 빠르지만 항상 최적해를 보장하지는 않습니다.

def greedy_coin_change(amount, coins):
    result = []
    for coin in coins:              # 큰 동전부터
        while amount >= coin:
            amount -= coin
            result.append(coin)
    return result

greedy_coin_change(63, [50, 10, 5, 1])   # [50, 10, 1, 1, 1]  최적!

def binary_search(arr, target):
    lo, hi = 0, len(arr) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if arr[mid] == target:
            return mid            # 찾음
        elif arr[mid] < target:
            lo = mid + 1          # 왼쪽 절반을 통째로 배제
        else:
            hi = mid - 1          # 오른쪽 절반을 통째로 배제
    return -1                     # 못 찾음

분기 한정 알고리즘과 백트래킹

탐색 도중 “이 아래에는 답이 없다”고 판단되면 그 가지를 통째로 잘라내고(가지치기), 이전 갈림길로 되돌아가 다른 길을 봅니다. 이 되돌아가기가 백트래킹입니다.

가지치기에 비유하면 — 나무를 키울 때 모든 가지를 다 키우기보다 가치 있는 가지만 남기고 불필요한 가지를 미리 쳐내는 것이 효율적입니다. 탐색도 최적해가 있을 가능성이 없는 부분은 아예 제외합니다.

예제 — 둘레가 9인 삼각형 화단은 몇 가지나 만들 수 있을까

삼각형이 되려면 두 변의 길이 합이 나머지 한 변보다 커야 합니다. 따라서 한 변은 둘레의 절반을 넘을 수 없습니다. 이 조건으로 탐색 범위를 미리 잘라 냅니다.

perimeter = 9
count = 0

a = 1
while a < (perimeter // 2):            # ❶ 한 변은 둘레의 절반 미만
    b = a
    while b <= (perimeter - a) // 2:
        c = perimeter - a - b
        if c < b:                      # ❷ 성립 불가 — 가지치기
            break
        if a + b > c and a + c > b and b + c > a:   # ❸ 삼각형 조건
            count += 1
        b += 1
    a += 1

print(f'만들 수 있는 화단의 수: {count}')   # 3
# (1, 4, 4), (2, 3, 4), (3, 3, 3)
구분분기 한정 알고리즘탐욕 알고리즘
접근 방식분기점마다 유망하지 않은 경로를 배제현재 단계에서 가장 좋은 선택을 함
최적해보장함보장하지 않음
계산 복잡도일반적으로 높음(분기마다 한계치 계산)일반적으로 낮음
분기 한정법은 최적해를 보장하지만 분기점마다 한계치를 계산해야 해서 모든 문제에서 가장 효율적이지는 않습니다. 문제의 특성과 제약 조건을 분석해 알맞은 방법을 고르는 것이 중요합니다.
핵심 포인트
  • 이진 탐색 O(log n) — 정렬된 데이터에서만. 매번 절반을 배제한다.
  • 탐욕법은 빠르지만(예: O(n)) 최적해를 보장하지 않는다. 문제 조건을 반드시 확인.
  • 분기 한정법은 가망 없는 가지를 잘라내고 백트래킹으로 되돌아간다.
  • 잘못 배제하면 답을 아예 못 찾는다 — 이것이 부분 탐색의 위험.

3-1 관계 기반 알고리즘의 이해 — 분할 정복 13주차

문제를 쪼개고, 전체와 부분 사이의 관계식을 찾아내 해결합니다.

문제를 분해하면 ① 구조가 잘 보이고 ② 부분 문제 코드를 재사용할 수 있으며 ③ 전체와 부분의 관계를 발견할 수 있습니다. 이 관계식은 대개 수학적 귀납법 형태로 표현되고, 그대로 재귀 함수가 됩니다.

문제관계식
1부터 n까지의 합f(1)=1,   f(n) = f(n−1) + n
팩토리얼f(1)=1,   f(n) = f(n−1) × n
하노이 탑 이동 횟수T(1)=1,   T(n) = 2 × T(n−1) + 1
계단 오르기(1칸 또는 2칸)f(1)=1, f(2)=2,   f(n) = f(n−1) + f(n−2)

분할 정복법의 3단계

퀵 정렬 — 기준(피벗)으로 갈라 놓는다

def quicksort(arr):
    if len(arr) <= 1:                 # 종료 조건
        return arr
    pivot = arr[0]
    left  = [x for x in arr[1:] if x <= pivot]
    right = [x for x in arr[1:] if x >  pivot]
    return quicksort(left) + [pivot] + quicksort(right)

quicksort([7, 5, 9, 4, 1])   # [1, 4, 5, 7, 9]

합병 정렬

8명을 두 조로 나눠 각각 줄 세운 뒤, 두 조의 맨 앞 사람끼리 비교해 작은 쪽을 앞에 세우기를 반복하면 전체가 정렬됩니다. 한쪽이 먼저 비면 남은 쪽을 그대로 이어 붙입니다.

[4, 5, 2, 1, 3, 8, 6, 7]
분할 → [4, 5, 2, 1] [3, 8, 6, 7]
     → [4, 5] [2, 1] [3, 8] [6, 7]
     → [4] [5] [2] [1] [3] [8] [6] [7]     ← 크기 1이면 이미 정렬됨

합병 → [4, 5] + [1, 2] → [1, 2, 4, 5]
     → [3, 8] + [6, 7] → [3, 6, 7, 8]
최종 → [1, 2, 3, 4, 5, 6, 7, 8]
def merge_sort(arr):
    if len(arr) <= 1:                    # 종료 조건
        return arr
    mid = len(arr) // 2
    left  = merge_sort(arr[:mid])        # 분할 + 정복
    right = merge_sort(arr[mid:])
    return merge(left, right)            # 병합

def merge(a, b):
    result, i, j = [], 0, 0
    while i < len(a) and j < len(b):
        if a[i] <= b[j]:                 # 앞 값끼리 비교
            result.append(a[i]);  i += 1
        else:
            result.append(b[j]);  j += 1
    result += a[i:]                      # 남은 쪽을 그대로 이어 붙임
    result += b[j:]
    return result

print(merge_sort([7, 5, 9, 4, 1]))   # [1, 4, 5, 7, 9]
퀵 정렬과 달리 합병 정렬은 항상 정확히 절반으로 나누므로, 최악의 경우에도 시간 복잡도가 O(n log n)으로 유지됩니다. 대신 합칠 공간이 따로 필요해 메모리를 더 씁니다.
스스로 해결하기
  1. 팩토리얼을 부분 문제로 분해하고, 관계식과 재귀 함수 코드를 각각 써 보자.
    f(n) = 1 × 2 × 3 × … × n = n! → f(1) = 1, f(n) = ?
  2. 선택 정렬의 비교 횟수가 n(n−1)/2임을 확인하고, 시간 복잡도가 O(n²)인 이유를 설명해 보자.
  3. 퀵 정렬에서 피벗을 가장 오른쪽 값 또는 가운데 값으로 바꿔 구현해 보고 결과를 비교해 보자.

한 번 계산한 답을 적어 두었다가 다시 쓰는 것. 그것만으로 속도가 극적으로 달라집니다.

막대는 함수 호출 횟수입니다. n을 오른쪽으로 밀어 보세요. 재귀는 O(2ⁿ)으로 폭발하지만, 동적 계획법은 O(n)이라 거의 늘지 않습니다.

방식진행 방향도구특징
하향식 (top-down)큰 문제 → 작은 문제재귀 + 메모이제이션기존 재귀 코드에 저장만 추가하면 됨
상향식 (bottom-up)작은 문제 → 큰 문제반복문함수 호출이 없어 더 빠름

하향식 — 메모이제이션

dp = {1: 1, 2: 1}

def f(n):
    if n in dp:            # 이미 계산했으면 꺼내 쓰기
        return dp[n]
    dp[n] = f(n - 1) + f(n - 2)
    return dp[n]

print(f(50))   # 즉시 출력

상향식 — 반복문으로 테이블 채우기

n = 10
dp = {1: 1, 2: 1}
for i in range(3, n + 1):
    dp[i] = dp[i - 1] + dp[i - 2]
print(dp[n])   # 55

계단 오르기 문제

한 번에 한 계단 또는 두 계단을 오를 수 있을 때 n개의 계단을 오르는 방법의 수입니다. 3개의 계단이면 ① 1+1+1 ② 1+2 ③ 2+1 로 세 가지입니다.

관계식:  f(1) = 1,  f(2) = 2,  f(n) = f(n-1) + f(n-2)

재귀만 쓰면 — 같은 계산을 반복해 O(2ⁿ)

def climbstairs(n):
    if n == 1: return 1
    if n == 2: return 2
    return climbstairs(n - 1) + climbstairs(n - 2)

print(climbstairs(10))   # 89

하향식 동적 계획법 — 계산한 값을 저장해 재사용

dp = {1: 1, 2: 2}

def climbstairs(n):
    if n in dp:
        return dp[n]
    dp[n] = climbstairs(n - 1) + climbstairs(n - 2)
    return dp[n]

print(climbstairs(10))   # 89

배낭 채우기 문제

최대 용량 w인 배낭에 물건을 담되, 무게를 넘기지 않으면서 가치의 합이 최대가 되게 하는 문제입니다. 세 가지 접근을 비교해 봅시다.

물건무게가치
1번2kg3
2번3kg4
3번4kg5
4번5kg6

① 브루트 포스 — 각 물건마다 담는다/안 담는다 두 가지이므로 경우의 수는 2ⁿ. 시간 복잡도 O(2ⁿ)으로 비효율적입니다.

② 탐욕 알고리즘 — 배낭 용량이 5kg일 때 가치가 가장 높은 4번(5kg, 가치 6)을 담으면 더 담을 수 없어 총 가치가 6입니다. 그러나 1번+2번(2+3=5kg)을 담으면 가치가 7입니다. 탐욕법으로는 풀리지 않습니다.

③ 동적 계획법 — 2차원 동적 테이블 dp[i][w]를 만듭니다. “i번째 물건까지 고려했을 때, 무게 한도가 w이면 얻을 수 있는 최대 가치”입니다.

wi > w 일 때:   dp[i][w] = dp[i-1][w]
                (i번째 물건이 너무 무거워 못 넣음 → 이전 값 그대로)

wi ≤ w 일 때:   dp[i][w] = max( vi + dp[i-1][w - wi],   # 넣는 경우
                                dp[i-1][w] )            # 안 넣는 경우
i \ w012345
0 (물건 없음)000000
1 (2kg, 3)003333
2 (3kg, 4)003447
3 (4kg, 5)003457
4 (5kg, 6)003457
 
items = [(2, 3), (3, 4), (4, 5), (5, 6)]     # (무게, 가치)
W = 5
n = len(items)
dp = [[0] * (W + 1) for _ in range(n + 1)]

for i in range(1, n + 1):
    wi, vi = items[i - 1]
    for w in range(W + 1):
        if wi > w:
            dp[i][w] = dp[i - 1][w]                       # 못 넣음
        else:
            dp[i][w] = max(vi + dp[i - 1][w - wi],        # 넣는 경우
                           dp[i - 1][w])                  # 안 넣는 경우

print('최대 가치:', dp[n][W])   # 7
표의 오른쪽 아래 dp[4][5] = 7이 답입니다. 탐욕법이 놓친 “1번 + 2번” 조합을 동적 계획법은 정확히 찾아냅니다.
핵심 포인트
  • 동적 계획법 = 관계식 + 저장(동적 테이블). 중복 계산을 없애 실행 시간을 크게 줄인다.
  • 분할 정복은 부분 문제가 독립적일 때, 동적 계획법은 부분 문제가 겹칠 때 쓴다.
  • 하향식(재귀+메모이제이션) / 상향식(반복문) 두 가지 방식이 있다.
  • 단점은 메모리 사용량 증가 — 저장할 공간이 필요하다.
  • 동전 교환처럼 탐욕법이 실패하는 문제도 동적 계획법은 최적해를 찾는다.
